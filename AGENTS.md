# AGENTS.md — operating manual for AI coding agents

You are working in the NetIgnite server: a LeiCraftMC full-stack Nuxt app (Nuxt frontend + Hono
backend in `server/`) plus the WebSocket gateway that NetIgnite agents connect to.
Follow the LeiCraftMC Style Guides: https://github.com/LeiCraftMC/Style-Guides.

## Non-negotiable

- Nuxt 4 `app/` srcDir; Tailwind v4 CSS-first; no `tailwind.config.js`. Dark-only (no toggle).
- The Hono backend lives in `server/` and owns `/api` — no `Bun.serve`, no `Main.main()`; init in
  `server/plugins/startup.ts`.
- Every API response uses the `{ success, code, message, data }` envelope via `APIResponse.*`
  (errors omit `data`).
- Validate with `hono-openapi`'s validator (`import { validator as zValidator } from "hono-openapi"`); routes in `server/lib/api/versions/v<n>/routes/<resource>/{index.ts, model.ts}`.
- Auth uses opaque bearer tokens (`<prefix>_<kind>_<id>:<base>`, `Bun.password`-hashed) — not JWT.
  See docs/10-auth.md.
- Frontend API access only through `useAPI`; global state via `AbstractStore` over `useState`;
  component-local form/UI state with `reactive()`/`ref()` is fine.
- Lucide icons only (`i-lucide-*`). Never hand-edit `*.gen.ts` under `app/api-client/` —
  regenerate with `bun run api-client:generate`.
- `nitro.rollupConfig.external: ["bun:sqlite"]` in `nuxt.config.ts`. WebSocket routes
  (`server/routes/ws/`) require `nitro.experimental.websocket = true` (Bun preset).
- Format with Biome before finishing. Conventional Commits.

## NetIgnite specifics

- **Port 18232** in dev and prod — a deliberate exception to the style guide's 12xxx rule, kept from
  v1 so existing compose files, proxies and agents keep working.
- **Agents** connect to `/ws/agent` (`server/routes/ws/agent.ts` → `server/lib/agents/`). The
  protocol is documented in `server/lib/agents/protocol.ts`; commands are only sent if the agent's
  HELLO listed the capability. Agent credentials are `netignite_agent_<token_id>:<secret>`; the
  secret is generated by the agent at enrollment (`server/lib/agents/auth.ts`) and never shown.
- **Devices** are owned by one user and shared per device with a role (viewer/operator/manager).
  Check access only through `DevicePermissions` (`server/lib/devices/permissions.ts`). Agents are
  never shared.
- Device status is polled server-side (`DeviceStatusService`) and cached; routes read the cache.
- **Transactions:** drizzle's bun-sqlite `transaction()` is synchronous and commits at the first
  `await` inside its callback. Do async work (password hashing) first and keep transaction
  callbacks synchronous (`.run()`, `.get()`, `.all()`) when atomicity matters.
- SQLite foreign keys are enabled in `DB.init` (`PRAGMA foreign_keys = ON`); `onDelete` rules rely
  on it.
- `scripts/import-v1.ts` imports a NetIgnite v1 database (bundled into `.output/import-v1.mjs` by
  `bun run build`).
- **Firmware** (`server/lib/firmware/`): `FirmwareCatalog` syncs Agent-ESP32 GitHub releases
  (`release.json` + flash images, SHA-256 and optional ECDSA signature checks) into
  `NETIGNITE_FIRMWARE_DIR`; no uploads. `NVSImage` writes ESP-IDF NVS v2 images byte-identical to
  Espressif's `nvs_partition_gen.py` (fixtures in `tests/fixtures/nvs/`); `ProvisioningImage` only
  writes the keys a release lists in `release.json` → `nvs.keys`. The firmware reads these NVS
  keys, so change them together with Agent-ESP32's `src/Config.h`.
- **Web installer** (`app/pages/dashboard/agents/[agent_id]/install.vue`): imports ESP Web Tools'
  prebuilt bundle `esp-web-tools/dist/web/install-button.js`; the package's ES modules need an
  older `@material/web` than npm resolves. All manifest parts are `blob:` URLs, so the enrollment
  token never appears in a URL.
- Run Biome's autofix only on the files you changed: on the whole tree it rewrites `@ts-ignore` to
  `@ts-expect-error`, which breaks `nuxt typecheck`.
- Tests: `tests/netignite.test.ts` (API + gateway with `tests/helpers/fake-agent.ts`),
  `tests/v1-import.test.ts`, `tests/firmware.test.ts` (catalog against a fake GitHub, flash image)
  and `tests/nvs.test.ts`.
